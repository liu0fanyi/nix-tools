# Clip 安装、更新与发布边界

## 需求与验收

- Clip 独立 flake/package 被 nix-tools 固定 revision 消费；更新脚本等待精确提交 CI 完整成功再更新父锁文件与 gitlink，失败不发布。
- Linux 使用 Nix store 稳定包路径，支持 standalone Home Manager；Windows 安装到固定用户目录，停止旧进程、校验 exe 后替换，doctor 成功才建立/启动计划任务。版本包含源码 revision 和协议版本。
- Android 使用固定 android-app-kit gitlink、相对依赖和只读 APP_KIT_READ_KEY；更新器、HTTPS 目录限制、SHA/大小/包名/签名验证归公共库，配对/接收归 Clip。
- 正式 APK 签名不变，只有一个手机启动入口，无 TV 入口。受限上传密钥只写 Clip 发布目录，无 shell/转发/删除。版本 APK 公网回下载验证后才更新清单；签名材料只在私有目录和 Secrets，备份写入不等于恢复演练。
- 纯事件下载进度，恢复前台仅一次快照，不恢复定时轮询；交接安装器后停止忙碌状态，不静默安装。
- 更新反馈靠近更新控件，成功 5 秒收起、错误保留，旧计时器不隐藏新消息；分享状态只报告准备/已广播，不声称远端已收到。
- 批量取消只操作当前待接收队列、跳过接收中项，保存失败恢复队列；不删已下载文件、不关闭接收。配对/更新/分享/接收反馈互不覆盖。
- 品牌图标和单色 smallIcon 保留，禁止重新添加无效 largeIcon 补丁。用户已确认重启后图标恢复，不沿用旧“尚未修好”状态。

## 公开发行候选（暂停）

普通用户公开稳定版仍需：独立用户密钥初始化与迁移；明确支持平台与可信 LAN 边界；许可证/NOTICE/SECURITY 与历史隐私扫描；无需私人 SSH 源的安装器；tag 制品校验、依赖清单与最小 CI 权限；干净环境安装升级卸载和协议模糊测试；支持周期及弃用规则。单设备撤销属后续评估。不将 nix-tools 私人配置作为应用发行物。
