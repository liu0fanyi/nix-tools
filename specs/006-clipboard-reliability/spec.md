# Clip 生命周期、限额与失败恢复

## 需求与验收

- 缓存最多 64 项、128 MiB 内联数据，单项内联 64 MiB，文件缓存和单接收批次各 20 GiB，批次最多 256 文件；这些不等于总 RSS/总临时盘上限。
- 历史缓存 30 分钟过期，每 30 秒维护；最新一项保留到替换。活跃快照不得淘汰，容量耗尽明确拒绝。Arc 快照在释放缓存锁后传输。
- TCP 最多 8 连接、同 IP 2 连接；未认证握手 5 秒、读写超时 30 秒。防重放集合 65,536 项满后拒绝新请求，不淘汰 nonce；不宣称跨重启防重放。
- 临时路径随机且原子创建，Unix 文件 0600；失败清理本批次。工作区持有文件锁，启动只清理无活跃持有者的本工具工作区。
- 逗号名称按尾部字段解析；新发送端提供安全旧字段并用 name_hex 保存完整 UTF-8。保留 v4 TCP 正文名称，不因非法 SHA 字符串 panic。
- Android 待接收 64 项、恢复 24 小时记录；凭据按来源/序号/已验证 SHA 去重，最多 4096 项、7 天。部分保存失败可重试；媒体写入与凭据不是跨系统原子事务。
- Android START_NOT_STICKY，强制停止后需用户重开；恢复前台检查 Rust 线程与前台服务，服务启动确认限 3 秒。耗时任务用异步/固定线程，忙碌标记不依赖 WebView 释放。
- 网络超时、拒绝、断连显示可操作提示并保留原 source，本地 I/O 错误不误映射为网络错误。
- 桌面失败暂存只保留一份 30 分钟，重试不重复保存已成功文件/图片。重试需用户确认，不是断点续传；源内容过期后需重新分享。

## 待验证边界

长锁屏、低内存回收、真实切网、大文件中断、部分保存失败去重及 Windows UI 仍需针对版本验收。外部分享准备失败需重新分享；Linux PID 取消竞争尚未专项改造。
