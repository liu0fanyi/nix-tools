# Clip 跨平台内容传输

## 基线与范围

实现位于 clipboard-sync 子模块；本规格回溯现有行为，不重新实施已有功能。桌面 Linux/Windows 与 Android 共享 protocol v4。UDP 53318 发现、TCP 53319 拉取、UDP 53320 手机发起配对。

## 需求与验收

- 支持文字、宽高大端编码加 RGBA 的图片、多文件和目录 ZIP；目录跳过符号链接、junction、特殊文件，保留空目录，接收不自动解压。
- 收到通告后由用户确认才拉取；文字写剪贴板不另存文本，图片保存 PNG 并在平台支持时写剪贴板，文件保存到平台下载目录；失败明确反馈，不覆盖同名文件。
- 接收写回防广播回环；同发送者连续相同内容去重，A→B→A 必须再次提示。桌面最新通知替换旧通知；Android 有限待接收队列单独管理。
- 暂停接收不妨碍本机发送，Android 保留未处理和失败记录。默认开启，设置持久化。无托盘不阻止 daemon 工作。
- 32 字节组密钥派生独立发现/传输密钥；UDP/TCP 内容加密、请求认证及进程内防重放。日志和 doctor 不输出正文或密钥。网络地址、时序和包长仍可见。
- Android 首次配对通过临时 X25519 加密通道，桌面明确允许并核对六位码；不把组密钥编进 APK。Android 10+ 后台不静默监听系统剪贴板。
- 支持 ACTION_SEND/SEND_MULTIPLE，热启动分享每次 Intent 只处理一次；后台接收服务持有并释放 MulticastLock。

## 不包含

独立设备身份、单设备撤销、已接收历史列表未作为现有能力。已撤销规格中的固定 2 分钟过期不作为当前任务；再次需要时另定范围。
