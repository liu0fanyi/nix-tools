# Helix 输入法试用

启用 Fcitx5 时，交互启动 `hx` 临时切英文。插入模式按 Esc/Ctrl-C 保存输入法
启用状态再切英文；i/a/I/A/o/O/c/Alt-c 恢复此前状态，select 模式也支持。
上次 insert 用英文，下次仍用英文。正常退出编辑器恢复最后保存的状态。
CLI 查询和管道不切换桌面输入法；状态每个进程独立，保存在运行目录并在退出清理。

配置源是 `home-manager/nix_modules/helix.nix`，按键使用同一脚本；无需改 Rime
词库或安装 Helix 补丁。关闭 Fcitx5 功能时仍使用原 Helix 和原有按键。
需要撤销本次方案时移除 package 包装及新增切换绑定，再由用户手动应用。

试用先确认中文 insert → Esc → hjkl → i 恢复中文，再手动切英文重复上述过程。
同时检查 I/A/o/O/c/Alt-c、select 模式、Ctrl-C，以及多个终端的独立恢复。
候选未上屏时 Esc 可能先被输入法消费，应单独测试；脚本不会强制提交候选。

这是按键绑定方案：宏、重复插入、自定义命令、项目配置覆盖及窗口焦点切换
可能绕过绑定；normal 手动开启中文也不会被持续强制关闭。搜索与命令行不单独
恢复中文。Rime 内部 ASCII 状态是否完整保留由实机验证，不宣称框架接口能查询它。
多个 Helix 状态文件独立，但实际切换仍作用于 Fcitx5 当前焦点上下文。
每次控制器调用最多等待 0.4 秒，输入法不在运行或总线不可用时继续编辑。

若这些限制影响体验，再把控制点放到 Helix 的真实模式变化处；上游路线是通用
插件/钩子，而 Fcitx5 专用补丁可先由 Nix 包维护。功能与验收见
[010 阶段 HX](../specs/010-host-configuration/tasks.md#helix-输入法配置试用阶段-hx)。
